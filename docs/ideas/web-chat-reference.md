# 未来方案：网页 AI 引用向本地 Agent 引用能力靠齐

状态：待实施。2026-10-18 用户要求仅记录构想，暂不修改功能。本文不是自动执行任务，也不是已交付能力说明；后续须得到用户启动实施的指示，再核对最新代码和实际安装版本。

## 目标与已确定的方向

新增来源的登录态与接口实测见 [豆包、千问国内版、Qwen 国际版调研](web-chat-new-sources-research.md)（2026-10-20，仅调研，未实施）。

让 `@网页端对话` 逐步具备本地 Agent 引用所讨论的体验：发送时自动提供预算内正文，需要更多时通过简单工具参数补读、搜索和查看图片。这里借鉴的是能力方向，本地 Agent 当前实现应在开发时重新核对，不能把讨论当成已上线行为。

- 网页统一采用 metadata-only：本地保存平台、账号范围、会话 ID、标题、链接和时间等索引，不保存完整正文镜像。
- 正文由 OpenCLI 实时获取，不新增跨调用的完整正文解析缓存，不生成完整文本快照文件。
- 单次请求可以复用刚获取的数据；预览和工具返回仍会随 DSH 正常聊天记录保存。
- 保留账号校验、引用权限检查、来源不完整提示；可读定位字段不等于任意会话读取授权。
- 取消向模型同时提供长 URI、短句柄和长 cursor 的设计，采用可读定位字段和数字范围。旧协议无需保留兼容是此前的设计选择，具体迁移影响仍须在实施前列明。

## 建议流程

1. `@` 菜单使用元数据索引，不提前获取所有会话正文。
2. 消息携带完整结构化定位信息，如 `source: web-chat`、`provider`、`accountScope`、`conversationId`。字段名是示意，实施时复用项目契约；不包含 Cookie 或 Token。网页 URL 用于打开原会话。
3. 发送后、模型运行前，校验引用与账号，通过 OpenCLI `detail` 获取正文。
4. 对有效分支的规范化内容计算版本，生成预算内的最近正文预览，注明获取时间、已展示范围、未展示范围和 `partial` 状态。
5. 模型能回答就直接回答；需要更多时调用读取、搜索或图片工具。
6. 后续调用重新获取来源内容。版本变化时提示刷新预览，不能继续按旧编号返回不同内容。

复制到其他对话应携带完整定位字段，而非只有标题；重新校验授权和账号。当前实现依赖本地账号索引，新对话或新环境缺少索引时如何重新验证并定位，是实施时必须处理的边界，不能声称仅凭字段已经可跨环境读取。

## 预览与工具设计

沿用此前讨论的官方预算思路：每个引用默认 `max(65536, floor(contextWindowTokens * 4 * 0.2))` 字节；显式 `maxReferenceBytes` 覆盖，模型容量未知时回退 64 KiB。按最终序列化 UTF-8 文本计量，不是精确 token 数，也不是多个引用共享的剩余空间。图片另行限制。

超预算先省略较早正文，再截短过长文本，明确区分整条消息省略、单条截短和图片尚未读取。不生成 `fullSnapshot` 字段。若来源 `partial: true`，只说“获取到 N 条”，不能说“会话总共 N 条”；搜索无命中也不能证明完整历史没有相关内容。

| 建议工具 | 主要参数 | 作用 |
| --- | --- | --- |
| `reference_read` | 定位字段、版本、起始消息编号、数量 | 补读正文 |
| `reference_search` | 定位字段、版本、关键词 | 返回命中编号和片段 |
| `reference_image` | 定位字段、版本、图片编号或稳定附件 ID | 返回真实图片内容块 |

名称与字段均为设计示意，优先复用实施时已有公共工具。正文编号建议从 1 开始。版本基于规范化内容，不因预览裁剪而变化，也不应因获取时间或临时签名 URL 更新而误变。当前网页协议没有独立工具调用记录，暂不承诺本地 Agent 式的工具细节补读。

## 已核对的 OpenCLI 能力与缺口

以下来自 2026-10-18 本地工作树源码检查，不是远端最新版或六个平台实机验收结果。OpenCLI 提供运行和浏览器能力，具体会话读取由本项目的 `opencli-plugin` 适配器实现。

| 能力 | 核对结果 | 所需处理 |
| --- | --- | --- |
| 列表与账号 | `sync-index` 返回账号范围和会话列表 | 复用现有元数据同步 |
| 正文 | `detail` 接受会话 ID 和可选账号范围，并校验账号 | 用于发送前预览 |
| 范围读取 | `detail` 没有消息范围参数 | 获取正文后在插件内截取 |
| 正文搜索 | 现有适配器没有正文搜索命令 | 获取正文后在插件内搜索 |
| 内容版本 | 当前 metadata-only 路径没有正文版本校验 | 在引用层补齐 |
| 工具记录 | 调用层只接受 user、assistant 角色 | 不虚构工具细节能力 |
| 分支 | ChatGPT 有当前节点祖先链，Claude 有分支处理；其他来源部分直接标记有效 | 按平台验证，不能一律宣称完整分支支持 |
| 降级 | DOM 回退会标记 partial，附件列表为空 | 明确不完整，不误报为空或无图片 |

每次补读或搜索可能重新获取整段正文，模型输出限制不等于网络获取限制。当前 runner 默认超时 60 秒；实施时需处理取消、超时和多引用等待，不让一次失败掩盖其他引用结果。

### 图片边界

| 来源 | 当前源码能力 |
| --- | --- |
| ChatGPT | 可识别图片标识；仅有 asset pointer 而无可用同源 locator 时不可下载 |
| Claude、DeepSeek、Kimi、Grok | 有附件提取，实际可读性取决于 locator、权限及响应 |
| Gemini | 当前 detail 返回空附件列表，尚不能通过此链路读取图片 |
| DOM 回退 | 文本读取，不能保证附件信息完整 |

通用附件下载器只接受同源 locator，拒绝跨域及重定向。不要为了适配 CDN 直接移除校验，应另行设计平台限定的安全下载路径。图片工具必须返回 DSH 实际图片块，返回路径或编号不等于模型看到了图片。

当前 metadata-only 路径还会在内存中保留一小时有效的附件定位信息。这不是正文缓存；后续需明确保留还是改为看图时重新 detail 获取。图片临时文件清理和宿主正常附件保存应分别处理，不能笼统承诺完全无存储。

## 后续实施与验收范围

优先复用当前 OpenCLI 命令，先完成正文预览、范围补读、正文搜索、版本校验和具体错误；图片按平台实际能力开放。缺失的平台能力在本项目适配器补齐，不预设必须修改 OpenCLI 核心。

- 核对当前安装的 OpenCLI、适配器与工作树版本，避免只测源码。
- 检查 metadata-only 设置、同步、搜索、附件和旧镜像清理的所有调用方；历史正文迁移或删除需单列影响，不因这份文档自动清理数据。
- 验证六个平台的账号切换、正文与 partial、分支、重复读取版本、真实图片及失败提示。
- 覆盖预览预算、多引用、源内容变化、历史继续、复制到新对话后重新授权、浏览器离线、登录过期和取消。
- 确认没有新增完整正文持久化或跨调用缓存；大对话重复获取的耗时和内存需实测。
- 按项目开发和环境规范进行测试、build、环境同步及实际验收；未测项写 NOT_RUN/BLOCKED。

当前只完成设计与源码核对，所有新增行为均未因此文档实施；原记录删除、平台失效或账号不可用后，没有快照可用于恢复补读。
