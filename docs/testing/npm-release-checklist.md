# npm 发版前测试规程

适用：`dsh-reference-anything` 的每次 npm 发布，包括补丁版和预发布版。执行发布任务的 Agent 必须先阅读本文件及根目录 `AGENTS.md`。本文件是执行约定，不是已经完成测试的证明，也不会自动执行浏览器检查。

执行入口见 [开发闭环](../development/workflow.md)：先核对候选版本，再运行 `npm run agent:release:prepare` 自动完成 check、双环境刷新及打包；完成本文人工/Browser Use 验收并填写记录后，运行 `npm run agent:release:gate`。不重复执行 prepare 已通过且候选未变化的同一检查。gate 不会自动发布，也不能判断手工证据的真实性。

## 1. 放行规则

- README、发布说明/功能卡及新功能 GIF 由 Agent 按 [发布素材与用户审稿](../development/release-materials.md) 主动准备。技术验收和素材就绪后，最终文字（含 GIF 字幕、标题、alt）必须交用户明确审核；未批准或批准后候选改变，不发布。
- 每次必须完成：候选版本核对、完整自动化检查、真实浏览器核心回归、Desktop 同步验收、实际 npm 包检查与安装冒烟、发布记录。
- 每次逐项验收全部已提供功能及来源，不按版本轮换或抽样；根据 diff、依赖变化及发布说明追加第 6 节的深入边界回归。已提供功能缺账号/数据/依赖时明确 BLOCKED，入口或未配置提示不能替代完整成功链路。
- 状态使用 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`、`N/A`。`PASS` 必须有本次候选产物的证据；`N/A` 必须解释为什么不适用。缺账号、缺依赖、工具不可用或未执行属于 `BLOCKED`，不能写成通过或不适用。
- 必测项、受影响功能或本次宣传功能存在 `FAIL` / `BLOCKED` 时，不发布。先修复并复测；无法解决则列明具体阻塞，由用户决定是否明确豁免，Agent 不自行放行。
- 既有测试跳过项逐项说明原因；新增 skip、降低断言、隐藏错误不能作为修复。不能用演示替身结果代替真实链路测试。
- 只复测受后续变更影响的检查；代码、依赖或构建配置变更后重新完整 check、打包并执行相关 UI/安装验收。测试后不能悄悄改变待发布内容。
- 用户已明确授权发版时，通过检查后继续完成发布，不重复请求确认；单纯要求写文档或运行测试不代表授权发布。

## 2. 确定候选版本和环境

- [ ] 记录日期、分支、HEAD、`git status --short`、候选版本及 npm dist-tag；未提交内容必须纳入候选说明，不覆盖用户工作。
- [ ] 阅读与上次发布相比的 diff、提交和发布说明，列出受影响模块、数据格式、公开接口、依赖与兼容性范围。
- [ ] 核对 `package.json` 的 name/version、exports、files、peerDependencies、scripts 与锁文件；版本无意外回退，计划发布版本尚未占用。
- [ ] 对照当前 npm 上一个版本和 dist-tag，确认稳定版与预发布版的发布目标。查询失败就是未确认，不能假定未发布。
- [ ] 英文/中文 README、版本功能卡和媒体资源与本次实际能力一致；不得写未经验证的兼容性承诺。
- [ ] 记录 Node、包管理器、DSH 宿主、浏览器和 Chat Import 实际版本，不抄旧报告数字。

环境分工遵守 `AGENTS.md`：

| 环境 | 发版时的职责 | 限制 |
| --- | --- | --- |
| `agent-browser-test` | Agent 使用 Browser Use 做真实 Web 回归 | 独立存储与工作区；本地插件链接当前仓库，Chat Import 默认 npm `0.26.1` |
| Desktop | 同步本次 build，实际窗口冒烟验收 | 不承担自动化实验，不使用 CLI 管理 Desktop profile |
| 用户亲自测试环境 | 留给用户 | 不覆盖配置，不用于 Agent 回归 |
| 演示动画环境 | 录制产品演示 | 不作为真实服务测试证据，不覆盖旧 GIF 备份 |

- [ ] 核对测试 Web 和 Desktop 的插件都链接到 `D:/dsh-reference-anything`；不能只检查 manifest，还要确认实际链接目标。
- [ ] 确认测试 Web 的 storage root 指向自身 profile，工作区和浏览器 URL 属于测试实例；记录端口、进程及日志位置。
- [ ] 自动化解析/导入边界测试使用 `tests/fixtures/chat-import-reader/` 中的合成会话和测试工作区文件；第 4.5 节另使用用户已授权的实际对话/来源验证真实链路。额外样例只写测试目录，不改真实 Agent 历史。
- [ ] 日志、截图和报告去除 token、API key、真实会话正文等隐私内容；不将登录 URL 写进提交或报告。

## 3. 自动检查与构建同步

运行 agent:release:prepare，保存退出码与生成的 release.json。它已执行 diff 检查、完整 check、打包与双环境刷新，不重复跑底层命令。检查测试数量、跳过原因、警告、启动日志和浏览器 console；独立脚本另执行其现有测试。任何失败先定位并修复，不能靠重跑掩盖。

## 4. 真实浏览器核心回归（每次必做）

在 `agent-browser-test` 使用 Browser Use 操作真实页面，记录关键截图、预期与实际结果。不能只用 DOM 单测或 HTTP 200 代替。普通菜单测试不发送消息；第 4.5 节必须按用户授权实际发送并核验模型读取和回答。

### 4.1 启动、设置与菜单

- [ ] 新页面和刷新后均可使用，插件设置可打开，没有长时间骨架屏、空白或持续报错。
- [ ] 插件启用/禁用及来源开关符合设置；重新启用不会重复添加入口、监听器或通知；恢复测试前设置。
- [ ] `@` 首次打开、重复打开、搜索、清空搜索、关闭和再次打开均正确；快速输入/切换来源时旧请求不覆盖新结果。
- [ ] 键盘上下移动、Enter、Tab、Esc 与鼠标选择符合界面提示；焦点可回到输入框，选中项不会错位。
- [ ] 短结果、空结果、长标题、中英文、空格路径和特殊字符不会破坏布局、搜索或引用编码。
- [ ] 每个已提供来源都列入测试表，来源列表以当前实现和 UI 为准，不能固定只测熟悉的几项。

### 4.2 来源覆盖矩阵

每个已提供来源至少实际选中一条并验证发现、搜索、插入、实际读取和基于内容的回答；仅菜单出现不算通过。外部服务未配置时验证引导与失败状态，但缺少真实成功链路仍记 BLOCKED，不能据此标 PASS。

| 来源 | 核心验证 |
| --- | --- |
| 文件与目录 | 文件插入，目录进入与引用的 Enter/Tab 语义，返回上级，空目录，中文/空格路径 |
| DSH 会话 | 搜索与选中测试会话，标题与目标一致，不指向其他会话 |
| 本地 Agent 会话 | 扫描测试样例，来源/标题正确，选中插入只读引用，不触发导入 |
| 网页历史对话 | 配置状态、同步状态及可用数据的引用；未登录、无数据或依赖缺失有提示 |
| 云盘文件 | 已配置时列表、目录导航和引用；未配置时给出正确入口，无假成功 |
| 指令 | 选择与插入符合指令语义，不误执行或误发送 |
| Skills | 选择与插入指向正确技能，不只是显示名称 |
| 本地插件 | 列表反映实际安装/启用状态，选择指向正确插件目录，普通依赖不冒充插件 |
| 其他新增来源 | 按当前 UI 加入矩阵，验证成功、空结果和失败路径 |

### 4.3 引用和导入

- [ ] 本地文件及本地会话引用可通过真实读取链路读到预期样例内容；引用保持只读，没有改源文件或自动导入。
- [ ] 选择导入先显示确认；取消后不创建会话，确认后只导入所选样例。
- [ ] Chat Import `0.26.1` 的真实导入成功，标题、角色、内容和目标会话正确；重复导入遵循当前去重/提示设计，不意外复制。
- [ ] 导入失败可见且可恢复；没有无限加载、假成功或无效 sessionId 导航。
- [ ] 导入与引用/摘要入口并存时不混淆；摘要生成属于第 4.5 节用户授权的测试范围，须使用指定官方账号模型并对照原文核验。

### 4.4 界面与收尾

- [ ] 中英文关键文案、浅色/深色主题、窄窗口与正常窗口无明显溢出、遮挡、图标缺失；至少检查菜单、设置和确认框。
- [ ] 可用键盘完成核心流程，焦点可见；图标按钮有可识别名称，禁用/加载状态不只靠颜色表达。
- [ ] 结束后清空输入草稿、恢复临时设置；仅清理明确的测试数据，不删除真实数据。记录仍保留的测试会话。

### 4.5 真实来源 → 官方账号模型 → 回答核验（每次必做）

用户于 2026-10-18 明确授权：Agent 可以引用用户实际对话及来源，使用用户 DeepSeek 官方账号来源的模型额度做实际验收。该授权持续适用于本项目的这些测试，不需每次重新询问；不包含其他模型提供商、购买额度或无关任务。不得以此前“不发送消息”的旧约定跳过此项。

- [ ] 只在 `agent-browser-test` 新建独立测试会话，按版本/来源标识。真实原始会话、文件和云端对象保持只读，不在用户日常会话里发送测试，也不把测试记录带入演示 GIF。
- [ ] 在实际模型选择器中核实提供商是用户登录的 **DeepSeek 官方账号**，记录 provider、模型 ID/名称和推理等级。不能只看模型名称带 DeepSeek，也不能换成第三方网关/API key 来源。账号不可用或额度耗尽时记 BLOCKED，不静默切换提供商。
- [ ] 先只读核对一条规模适中的真实对话，确定其中 2–3 个可检验的具体事实作为预期；优先非敏感的项目技术记录，排除凭据和与验收无关的隐私。预期答案不要写进给模型的提示，也不要手动粘贴正文代替引用读取。
- [ ] 用真实 `@` 菜单查找、选择并插入引用，再实际发送短提示，例如：“只依据这条引用，说明讨论的问题、最终决定和一个具体细节；缺少信息就明确说明。”核对插入目标确为所选来源，不能只凭标题判断。
- [ ] 检查轨迹里的真实读取链路：宿主原生引用展开或 `reference_read` 等实际工具调用、参数、返回内容/范围与权限结果。来源标识和正文必须对应；不要求所有来源都走同一个工具，但必须有真实内容到达模型的证据。
- [ ] 将回答逐项对照预期事实；不得把流畅回答、标题复述或模型自己声称“读到了”当作成功。读取报错、空内容、错误会话、只靠猜测回答都判失败；回答诚实表示“无法读取”也说明产品成功路径未通过。
- [ ] 每次覆盖全部已提供来源及功能，逐项登记，不轮换抽样：每个对话/文件/云盘等内容来源验证真实发现、搜索、插入、读取与模型回答；每种已提供 Agent/网页提供商单独列项。导入、摘要、同步、附件、设置、快捷操作等各自验证完整成功流程，涉及权限、写入和恢复的功能补失败/取消/边界检查。指令、技能等按实际语义验证；纯 UI 操作不必消耗模型额度。缺登录、数据或运行条件记 BLOCKED，不把提示正常当成功。完整矩阵随当前实现更新，不能用演示 fixture 替代。
- [ ] 引用问答验收使用“仅可查看”模式，发送前核实实际按钮状态；导入等写操作专项按其单独确认流程执行。
- [ ] 自然语言可用性必须另测简单与复杂模糊请求：只插入真实引用并描述用户目标，不提供工具名、字段、ID、版本、分页位置或答案。简单例：“帮我看看这段聊了什么，现在做到哪了？”复杂例：“结合这两段记录，整理做过什么、证据和还没解决的问题，截图里相关的地方也看看。”按来源实际内容选择目标。
- [ ] 模糊请求核验：模型自行选择读取/搜索/图片入口，需要时续页；事实与来源对应，明确区分历史计划、工具执行结果与已验证完成。正文不足时不能只凭预览宣称覆盖全会话；未看像素不能描述图片。歧义可合理澄清，禁止编造。记录原始短提示、实际工具轨迹、答案核对；精确参数测试通过不能代替模糊请求通过。
- [ ] Codex 必须追加真实长会话与带图会话专项，记录原文件大小、规范化消息/工具/图片数量、预览范围和实际返回字节。用自然语言问题追问早期事实与截图，确认模型不会只依据尾部预览下结论；检查真实图片 block、图片答案和原图一致。另核验长工具文本的 textOffset 续读及版本稳定性。合成 fixture、其他 Agent 图片或旧扫描器性能不能替代。
- [ ] 涉及摘要、图片/附件、分页或长会话读取的改动时，追加对应真实样例；确认摘要事实正确、附件实际可读取，不能只验证引用 chip。
- [ ] 对引用不存在、失效或无权限的路径做受控失败检查，确认无越权读取、错误可见且模型不编造正文。避免修改/破坏真实来源来造失败，用测试引用或临时样例触发。
- [ ] 控制用量：每个案例先用一次短请求，仅按定位需要追加；只读取完成验收必要的片段，不进行无上限重试或批量总结历史。记录模型实际用量（若界面提供）；无法获取时写未知，不估算为零。
- [ ] 证据记录来源类别及本地可定位标识、预期事实、提示词、测试 sessionId、模型提供商、读取轨迹、实际回答对比、结论和用量。含真实正文的详细记录只放本地忽略目录；可提交报告仅放脱敏结果，不写 token 或完整私人会话。
- [ ] 在发布记录的 `checks.browser` 证据中明确列出这些实际请求结果；只完成菜单/UI 及合成样例不能将 browser 标为 PASS。测试完成保留必要本地验收证据、清空未发送草稿，并说明留存的测试会话。

### 4.6 失败诊断与复测（有失败必做）

- [ ] 按 [官方 Session Log 诊断](session-log-diagnosis.md) 导出失败会话，核对 sessionId、事件链、引用读取结果与模型响应；不要仅凭回答文本猜原因。
- [ ] 保留原失败日志，修复根因并在相同实际来源/输入下复测；记录修复前后证据。缺少会话日志时说明原因并使用宿主/浏览器日志，不把日志不可用当成功。
- [ ] 无根因证据或未真实复测，不得把 FAIL/BLOCKED 改成 PASS；发版报告保留失败、修复和复测记录。
- [ ] 按诊断规程清理不再需要的官方日志 ZIP、解压内容及本次下载副本；保留脱敏报告，更新证据引用并验证删除结果。仍需保留的阻塞案例注明原因和路径，不删除宿主原始会话。

## 5. Desktop 同步与冒烟（每次必做）


- [ ] 确认旧 Desktop 进程（含托盘）已退出并重新启动，记录所用应用路径与版本。
- [ ] 在真实窗口确认加载当前插件，设置可打开、`@` 菜单可用，实际插入一个测试文件引用后清空草稿。
- [ ] 受影响的 Desktop 专属能力进行对应窗口验收；无法访问窗口时记 `BLOCKED`，不能用 Web 结果代替。
- [ ] 记录 Desktop 与 Web 的结果差异。安装/进程启动成功不等于界面功能成功。

## 6. 按改动追加回归

对每行记录“适用/不适用及原因”。受影响功能除正常路径外，至少验证一个边界或失败路径。

| 改动范围 | 追加检查 |
| --- | --- |
| 本地 Agent 适配器/解析 | 相关格式的合成样例；空/损坏/截断文件，缺失目录，编码、时间戳、工具消息、压缩标记；大文件/分页/取消；单来源失败不拖垮其他来源 |
| 扫描与缓存 | 首次与重复扫描，新增/修改样例后的刷新，失效处理，多来源去重；旧请求不能覆盖新查询；不把其他账号/工作区缓存混入 |
| Chat Import 依赖与生命周期 | 已安装兼容版本、不兼容版本、未安装和加载失败；版本提示与安装动作；独立插件不重复安装/注册、不被引用插件卸载。破坏性场景用临时 profile，不改 Desktop |
| 网页同步/OpenCLI | 登录/未登录、账号范围不匹配、超时、限流、浏览器扩展缺失、增量同步边界、分页、取消与重试；不重复或串账号，日志不泄露凭据 |
| 云盘/OpenList/下载 | 鉴权失败、目录分页、下载目录验证、文件名冲突、失败清理；不越界写入、不接受不可信下载 URL；不覆盖已有用户文件 |
| 引用编码/读取/保留策略 | 编解码往返、损坏/未知 URI、转义、范围切片、附件、超限内容及清理；旧引用仍可读，拒绝非法输入且错误可理解 |
| 设置/快捷词/本地插件 | 保存与重启持久化，默认值和旧设置兼容，重名/空值/冲突，来源隐藏与排序，停用与恢复，局部失败不影响其他来源 |
| 升级与功能卡 | 当前/新版本、离线、请求失败，重复点击，版本/媒体缺失；不向错误 profile 安装，不把失败显示为成功 |
| UI/样式/图标 | 主题、语言、缩放、窄屏、长文本、菜单贴边定位、滚动与键盘操作；检查实际渲染，不仅断言 class 名 |
| 公共 exports/协议 | 现有调用方与旧引用兼容，入口文件和类型声明齐全，错误形状稳定；不依赖开发目录中的未发布文件 |
| 依赖/SDK/构建 | 锁文件一致，支持范围内最低 SDK 和当前宿主的相关兼容测试；新增可选依赖缺失时能降级；记录未验证平台，不泛称全平台通过 |
| 性能/并发 | 用固定样例比较冷/热打开、扫描、搜索和导入；记录样例规模与耗时，检查重复监听、并发请求和长任务取消；无依据不报性能提升 |

## 7. npm 实际产物与安装验收（每次必做）

不能只测仓库链接：本地 `node_modules` 和源文件可能掩盖 npm 包漏文件。

- [ ] 使用最后一次 prepare 生成的实际 tgz 和 pack.log 检查文件清单，不再另打包；候选改变则重新 prepare。
- [ ] 两条命令的生命周期脚本可能执行构建；若再次构建，按双环境约定同步加载，不把旧运行实例当作当前产物。
- [ ] 检查 `.tgz` 内容：main、types、全部 exports 的目标文件、客户端 bundle、Cordis patch、locale、图标、功能卡及媒体、OpenCLI 子插件、vendored reader 与 LICENSE/NOTICE 均按实际引用存在。
- [ ] 检查包不包含凭据、认证链接、真实会话、个人路径日志、测试缓存、无关录屏或 `node_modules`；记录文件数和 unpacked size，调查相对上版的异常膨胀。
- [ ] 对实际 `.tgz` 计算 SHA-256，记录文件名及 npm pack 输出的 integrity/shasum，将验证结论绑定到这份包。
- [ ] 在临时干净安装目录或临时 DSH Web profile 安装该 `.tgz` 和明确的宿主依赖，从解包后的真实包启动；不得链接回仓库来掩盖缺文件。
- [ ] 临时 profile 使用独立存储与工作区，安装 Chat Import `0.26.1`；浏览器验证启动、设置、引用插入及合成样例导入。它只是包验收临时实例，不替代四个常驻环境。
- [ ] 从上一个 npm 版本升级到候选 `.tgz`，保留合成设置、引用和导入会话，验证升级后可读且未重置；首次发布时注明此项不适用。
- [ ] 安装/升级过程无不可解释的 peer 错误、加载失败或开发路径依赖。只读检查上版可用性，不为方便修改用户日常环境。
- [ ] 候选未发布时，使用本次实际 `.tgz` 代替线上 npm 升级目标；不能先发布再补测。Chat Import 另列真实安装矩阵：未安装、独立旧版、独立兼容新版、用户禁用、安装失败与重试。记录安装前后依赖声明、bundle 启用状态和实际 API；启动不偷偷升级已有版本，显式安装/升级后才启用，不覆盖用户禁用决定，不降级新版，不重复注册或随引用插件卸载独立 Chat Import。
- [ ] Chat Import 安装传输可在隔离测试宿主中将已核对的精确版本映射到对应本地 `.tgz`，但保留生产兼容性判断和官方 Plugin Manager 的真实安装/启用流程，报告明确说明这一测试替换。未来尚不存在的版本只能标为合成边界测试，不能冒充已发布版本验收。
- [ ] 若要调整主测试 profile 做安装试验，先保存配置，结束恢复本地 link 并验证；优先使用上述临时 profile。

当前 `prepublishOnly` 为 `npm run check`，只是自动化兜底，不覆盖 Browser Use、Desktop 或包安装验收。发版前不得删除或绕过它来跳过失败。

## 8. 记录、门禁与发布

### 累计完整报告（必需）

本地维护 .codex-tmp/release-check/<version>/acceptance-report.md；既有报告保留原路径。每次交付涵盖本版本全部基础/新增功能、历史通过、失败与复测、跳过和未测项，不只报本轮增量。

开头依次列：当前 FAIL（无则明确写无）、BLOCKED/NOT_RUN、候选信息、完整逐项矩阵。每项记录稳定编号、环境/候选、输入或来源、预期/实际、状态和证据路径。历史失败保留原因与复测索引，详细经过按链接追溯，不全文重复粘贴；旧候选 PASS 不继承为当前 PASS。

公开仅维护 docs/testing/releases/<version>-summary.md：候选、总体结论、未关闭问题、阻塞和下一步，不包含私人正文、登录链接或机器流水。现有 .gitignore 仅放行 0.5.0 摘要，新增版本时加入对应精确例外。公开摘要不代替本地完整交付。

### release.json

- browser、desktop、packageContents、cleanInstall、upgrade、changeReview、readme、releaseNotes、demos 均需 PASS、summary 和存在的本地 evidence 文件。无需新素材时说明原因；首次发布 upgrade 记录无旧版及首次安装证据，不留空。
- redGreen、breakCheck、ci 为 PASS 或有理由的 N/A；适用的 CI 必须是当前 HEAD 已完成的成功检查。
- editorialApproval 按[审稿流程](../development/release-materials.md)填写用户明确批准及证据，并匹配 sourceDigest、packageSha256。
- NOT_RUN 表示尚未执行，BLOCKED 表示条件阻塞，FAIL 表示已执行失败；三者均不放行。状态不能代替真实证据，gate 只验证字段、文件和候选一致性。

证据路径可相对仓库；详细证据无需 Git 跟踪。官方日志按[诊断规程](session-log-diagnosis.md)脱敏并清理临时副本，不删除原始会话或候选包。

验收与审稿完成后执行 agent:release:gate。仅在已有发布授权时发布记录中的同一 tgz，明确 dist-tag，核验 registry 版本和 integrity；失败不自动递增版本。prepublishOnly 只是自动检查兜底，不替代此流程，不得绕过失败。
