# npm 发版前测试规程

适用：`dsh-reference-anything` 的每次 npm 发布，包括补丁版和预发布版。状态词、证据和失败处理遵守 [代码与验收标准](../development/standards.md#证据规则)，本文不复述。

流程：核对候选 → `npm run agent:release:prepare`（复用同一候选已通过的 verify，否则自动跑 check；打包；刷新测试 Web 与 Desktop）→ 本文第 4–7 节验收并写报告 → 文案审核 → `npm run agent:release:gate`。gate 不发布，也不判断报告内容是否真实。

## 1. 放行规则

- 每次必做：候选核对、prepare、浏览器回归（第 4 节）、Desktop 冒烟（第 5 节）、包内容与干净安装（第 7 节）、验收报告（第 8 节）、文案审核。
- 受影响范围由本次 diff、依赖变化和发布说明决定（第 6 节）。受影响的功能做完整验收；未受影响的已提供功能做冒烟。用户于 2026-11-11 决定以此取代原"每次全量、不抽样"的规定。
- 必做项、受影响功能或本次宣传功能存在 FAIL / BLOCKED 时不发布。无法解决的阻塞列明原因，由用户决定是否豁免。
- 只复测受后续变更影响的检查：代码、依赖或构建配置变化后重新 prepare，并重做相关 UI/安装验收。
- 用户已明确授权发版时，通过 gate 后继续发布，不重复请求确认；只要求写文档或跑测试不代表授权发布。

## 2. 确定候选版本和环境

- [ ] 记录日期、分支、HEAD、`git status --short`、候选版本及 dist-tag；未提交内容纳入候选说明。
- [ ] 阅读与上次发布的 diff、提交和发布说明，列出受影响模块、数据格式、公开接口和依赖。这份列表决定第 4.4 节分级和第 6 节追加项。
- [ ] 核对 `package.json` 的 name/version、exports、files、peerDependencies 与锁文件；版本未被占用（查询失败即未确认）。
- [ ] 记录 Node、包管理器、DSH 宿主、浏览器和 Chat Import 实际版本。
- [ ] 两个环境的插件实际链接到当前仓库，测试 Web 的 storage 与 session 指向自身 profile（prepare 的刷新脚本会校验）。
- [ ] 日志、截图和报告不含 token、API key、真实会话正文；不把登录 URL 写进提交或报告。

## 3. 自动化检查

prepare 已包含：同一候选 verify 通过时复用其 check 日志，否则执行 `git diff --check` 与完整 `npm run check`（typecheck → Vitest → build）；随后用这份 build 打包（`--ignore-scripts`，不重建），刷新两个环境。三平台结果看 CI 对同一 SHA 的运行。

- [ ] 记录通过/失败/跳过数量；阅读警告，区分环境警告与新回归。
- [ ] 变更涉及未被 Vitest 覆盖的独立脚本时，另执行该脚本的自检。
- [ ] 查看启动日志和浏览器 console：无资源 404、插件加载失败、未处理异常或重复注册。

## 4. 真实浏览器回归（agent-browser-test）

### 4.1 启动、设置与菜单行为

- [ ] 新页面和刷新后可用；插件设置可打开，无长时间骨架屏或持续报错。
- [ ] 来源插件开关：关闭后分组、设置分区和模型读取一起消失；重新启用不重复添加入口或监听器；恢复测试前设置。
- [ ] `@` 首次打开、重复打开、搜索、清空、关闭再打开正确；快速输入/切换来源时旧请求不覆盖新结果。
- [ ] 键盘上下、Enter、Tab、Esc 与鼠标选择符合提示；焦点回到输入框。
- [ ] 空结果、长标题、中英文、空格路径、特殊字符不破坏布局、搜索或引用编码。
- [ ] 指令、Skills 的选择与插入符合语义，不误执行或误发送（这两类不需要模型读取）。

### 4.2 引用与导入

- [ ] 引用只读：不改源文件、不自动导入。
- [ ] 导入先显示确认；取消不创建会话；确认后只导入所选样例，标题、角色、内容正确；重复导入按设计去重；失败可见可恢复。

### 4.3 界面

- [ ] 中英文、浅色/深色、窄窗口与正常窗口无溢出、遮挡、图标缺失（菜单、设置、确认框）。
- [ ] 键盘可完成核心流程；图标按钮有可识别名称；禁用/加载状态不只靠颜色表达。
- [ ] 结束清空草稿、恢复临时设置；只清理明确的测试数据。

### 4.4 真实来源 → 官方账号模型 → 回答核验

用户于 2026-10-18 授权：Agent 可以在 agent-browser-test 引用用户实际对话及来源，使用其 DeepSeek 官方账号的模型额度验收。不含其他提供商或购买额度。

共同要求：

- 只在 agent-browser-test 新建测试会话；原始来源只读。
- 在模型选择器核实提供商是 **DeepSeek 官方账号**，记录模型和推理等级；不可用或额度耗尽记 BLOCKED，不换提供商。
- 用真实 `@` 菜单插入引用（这一步同时覆盖该来源的发现、搜索、插入），使用"仅可查看"模式发送。
- 检查读取轨迹：实际工具调用、参数、返回内容与权限结果；再将回答与预期事实逐条对照。流畅回答、复述标题或模型自称"读到了"都不算成功。
- 控制用量：每个案例先发一次短请求，按需追加；记录实际用量（界面没有就写未知）。

按第 2 节的受影响列表分级：

| 级别 | 适用 | 做什么 |
| --- | --- | --- |
| 完整 | diff 碰到的来源/功能 | 先只读确定 2–3 个可检验事实；插入、发送、核对轨迹和回答；补一个失败路径（失效/无权限引用，用测试引用触发，不破坏真实来源） |
| 冒烟 | 其余已提供的内容来源（文件与目录、DSH 会话、本地 Agent、网页对话、云盘、本地插件及新增来源） | 每个来源一条短请求：读到正文，回答对 1 个事实 |
| 专项 | 改了读取协议、分页、图片/附件、长会话或工具描述时 | 简单与复杂两类模糊自然语言请求（不给工具名、ID、答案）；Codex 真实长会话与带图会话（早期事实、截图、textOffset 续读） |

缺登录、数据或运行条件的来源记 BLOCKED，不把"提示正常"当成功。证据写入报告：来源标识、预期事实、提示词、测试 sessionId、读取轨迹摘要、回答对比、结论、用量。含真实正文的细节只放本地忽略目录。

### 4.5 失败诊断（有失败时）

按 [官方 Session Log 诊断](session-log-diagnosis.md) 导出、定位、修复、在原输入下复测，用完清理日志副本。

## 5. Desktop 冒烟

prepare 已重启 Desktop（含托盘进程）。

- [ ] 实际窗口加载当前插件；设置可打开；`@` 菜单可用；插入一个测试文件引用后清空草稿。
- [ ] 受影响的 Desktop 专属能力做对应窗口验收；无法访问窗口记 BLOCKED，不用 Web 结果代替。
- [ ] 记录与 Web 的差异。

## 6. 按改动追加回归

只列出本次 diff 命中的类别（未列出即不适用），每个命中类别除正常路径外至少验证一个边界或失败路径。

| 改动范围 | 追加检查 |
| --- | --- |
| 本地 Agent 适配器/解析 | 相关格式的合成样例；空/损坏/截断文件，缺失目录，编码、时间戳、工具消息；大文件/分页/取消；单来源失败不拖垮其他来源 |
| 扫描与缓存 | 首次与重复扫描，新增/修改样例后刷新，失效处理，多来源去重；旧请求不覆盖新查询 |
| Chat Import 依赖与生命周期 | 真实安装矩阵：未安装、独立旧版、兼容新版、用户禁用、安装失败与重试。启动不偷偷升级，显式安装后才启用，不覆盖禁用决定，不降级，不随引用插件卸载。破坏性场景用临时 profile。可在隔离宿主把精确版本映射到本地 tgz，报告注明替换 |
| 网页同步/OpenCLI | 登录/未登录、账号范围不匹配、超时、限流、扩展缺失、增量边界、分页、取消与重试；不串账号，日志不泄露凭据 |
| 云盘/OpenList/下载 | 鉴权失败、目录分页、下载目录验证、文件名冲突、失败清理；不越界写入、不覆盖已有用户文件 |
| 引用编码/读取/保留策略 | 编解码往返、损坏/未知 URI、范围切片、附件、超限内容；旧引用仍可读 |
| 设置/快捷词/来源插件 | 保存与重启持久化，旧设置迁移，重名/空值/冲突，来源隐藏与排序，停用与恢复，局部失败不影响其他来源 |
| 设置/存储/引用格式变化 | 从上一个 npm 版本升级到候选 tgz：合成设置、引用和导入会话升级后可读且未重置（填 `upgrade`） |
| 升级与功能卡 | 离线、请求失败、重复点击、版本/媒体缺失；不向错误 profile 安装 |
| UI/样式/图标 | 主题、语言、缩放、窄屏、长文本、菜单贴边、滚动与键盘；检查实际渲染 |
| 公共 exports/协议 | 现有调用方与旧引用兼容，入口文件和类型声明齐全，错误形状稳定 |
| 依赖/SDK/构建 | 锁文件一致，最低支持 SDK 与当前宿主兼容；可选依赖缺失可降级 |
| 性能/并发 | 固定样例比较冷/热打开、扫描、搜索和导入耗时；无依据不报性能提升 |

## 7. npm 包内容与干净安装

- [ ] 检查 prepare 生成的 tgz：main、types、全部 exports 目标、客户端 bundle、Cordis patch、locale、图标、功能卡及媒体、OpenCLI 子插件、vendored reader、LICENSE/NOTICE 齐全；不含凭据、真实会话、个人路径日志、测试缓存或 `node_modules`；记录文件数和 unpacked size，调查异常膨胀。
- [ ] 记录 tgz 的 SHA-256 与 integrity（`release.json` 已有）。
- [ ] 在临时 DSH Web profile（独立存储与工作区）从该 tgz 安装并启动，不链接回仓库；验证启动、设置、一次引用插入。只是包验收实例，不替代常驻环境。
- [ ] 安装过程无不可解释的 peer 错误、加载失败或开发路径依赖。
- [ ] 升级与 Chat Import 安装矩阵见第 6 节，命中时才做。

## 8. 记录与发布交接

每个版本只维护一份 `docs/testing/releases/<version>-acceptance-report.md`，每轮验收更新其中的当前矩阵；历史经过由 git 保留，不在报告内重复附录。原始日志与截图放 `.codex-tmp/release-check/<version>/`。

- 开头先列当前 **FAIL**（编号、问题、影响、修复/复测状态），无则写"当前 FAIL：无"；紧接着列 BLOCKED 与未测项。
- 每项有稳定编号（如 `B-01`），写环境/候选、来源标识、预期、实际、状态和证据路径。`release.json` 的 `checks.*.ref` 与审稿的 `ref` 指向这些编号，gate 会核对。
- 修复后的失败项保留首个异常、原因、修复和复测结果，不以最终 PASS 覆盖经过。

```markdown
# <version> 发布验收

当前 FAIL：无
BLOCKED / 未测：…

- 候选：分支 / HEAD / 版本 / dist-tag / 上一个 npm 版本
- 环境：Node / pnpm / DSH / 浏览器 / Chat Import / Desktop 路径
- 包：tgz 路径 / SHA-256 / integrity
- 受影响范围：…（决定 4.4 分级与第 6 节）

| 编号 | 项目 | 状态 | 预期与实际 | 证据 |
| --- | --- | --- | --- | --- |
| A-01 | 完整 check（复用 / 新跑） | | | |
| B-01 | 浏览器 4.1–4.3 | | | |
| B-02… | 4.4 逐来源（完整 / 冒烟 / 专项） | | | |
| D-01 | Desktop 冒烟 | | | |
| R-01… | 第 6 节命中项 | | | |
| P-01 | 包内容 / 干净安装 | | | |
| E-01 | 文案审核（用户原话、对话定位） | | | |

## 结论
可发布 / 阻塞。写明是否已发布，不把测试通过写成发布成功。
```

获得发布授权且 gate 通过后，发布已验收的那份 tgz，使用明确 dist-tag，发布前重新核对包哈希。不要用直接 `npm publish` 绕过 gate。发布后查询 registry 的版本、dist-tag 和 integrity 与本次包一致；网络/认证失败或只生成包都不算已发布，不自动递增版本重试。
