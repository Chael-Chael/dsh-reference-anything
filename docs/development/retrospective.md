# 复盘与经验晋升

参考 [wquguru 对 magpie 的实践分析](https://x.com/wquguru/status/2109650264601117141)：轻量入口、证据化教训、重复问题晋升为规范。不把原帖项目统计或未公开的夜审触发方式当成本项目已实现能力。

较大任务交付、修复后返工、发布前或用户要求复盘时执行。可以每日手动调用；未配置定时任务，不声称有自动夜审。用户要求定时复盘时再配置调度。

1. `npm run agent:retro -- <git-revision-range>` 输出提交与文件变化；默认最近一天。提交时间用于筛选，报告日期使用 Asia/Shanghai。
2. 阅读实际 diff、测试结果、PR/issue 和发布报告，只找：修完返工、不该合入、验收不足；也保留有效做法。
3. 每条写事实、证据、适用范围及下次如何验证；证据不足列待核查，不写成教训。
4. 更新 `LESSONS.md`，同一规则在三个不同日期有独立证据才晋升到 `standards.md`，更新原条目链接。用户直接要求的规则不受三次门槛限制。
5. 能用测试/断言防止复发的，优先补可执行检查；同步文档路由，不无限增长根 AGENTS。

脚本只收集材料，不自动判定事故、不自动加 Seen、不自行提交/合并/发布。Agent 可维护项目账本，不修改全局个人记忆。
