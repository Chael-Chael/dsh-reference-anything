# 代码与验收标准

本文是测试证据规则的唯一出处；其他文档只链接，不复述。

## 修改前

1. 用 `npm run agent:context` 查看工作区、脚本和入口；读取子系统地图及相关源码。
2. 写清用户可见结果、受影响调用方/配置/exports/测试及验收方法。小改动放当前对话，多阶段任务写 `docs/development/tasks/<slug>.md`。
3. 优先复用已有服务、官方组件与标准库，不为几行代码引入依赖或框架。

## 修改与回归

- Bug 先复现报告人的输入和界面，再检查共享实现的同类调用方，不只修截图中一个来源。
- 新增非平凡分支、循环或解析器有小而有意义的回归测试；文档和简单格式调整无需形式化测试。
- **red/green**（仅修 bug）：回归测试在旧实现上因目标行为失败，修复后通过。用临时 worktree 验证旧实现，不回滚用户工作目录；编译失败、缺依赖和跳过不是有效 red。
- **break check**（仅解析、安全、数据写入、去重的关键断言）：在隔离副本中故意破坏目标条件，测试必须抓到。
- 代码搬移保留错误处理、校验与取消逻辑；失败不能被吞掉后显示成功。日志不泄露凭据或会话正文。
- README 中英文同步，保留开头展示区。UI 使用现有 DSH 组件和 `design.md`。

## 证据规则

- 状态只用 `PASS`、`FAIL`、`BLOCKED`、`N/A`。PASS 要有本次候选的证据；N/A 写原因；缺账号、依赖、工具或没执行一律 `BLOCKED`，不写成通过。
- 构建、单测、进程启动、HTTP 200 都不等于界面验收；Web 与 Desktop 分别报告。演示环境的替身结果不证明真实接口可用。
- 证据绑定候选：代码、依赖或构建变更后，受影响的旧结果失效。
- 真实功能验收失败：先按 [官方 Session Log 诊断](../testing/session-log-diagnosis.md) 定位首个异常，修根因，在原输入下复测；不靠重发碰运气。原 FAIL 保留在记录里。
- 新增 skip、降低断言、隐藏错误不算修复。

## 完成条件（日常交付）

- `npm run agent:verify`：diff 检查 + 完整 check + 刷新测试 Web。失败不能忽略。
- 在 `agent-browser-test` 完成受影响的浏览器验收。Desktop 只在[环境约定](environments.md#desktop-何时验收)规定的情况下验收。
- 审查最终 diff：越界改动、泄密、接口/旧数据兼容，列明没跑的测试。
- 有 PR/CI 时，只接受当前 HEAD 已完成且成功的必要检查；queued、running、cancelled、旧 SHA 都不算通过。
- 发版另按 [发版规程](../testing/npm-release-checklist.md)。
