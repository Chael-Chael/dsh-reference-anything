# 代码与验收标准

## 修改前

1. 用 `npm run agent:context` 查看工作区、脚本和入口；读取子系统地图及相关源码。
2. 写清用户可见结果、受影响调用方/配置/exports/测试及验收方法。小改动放当前对话，多阶段任务写 `.codex-tmp/tasks/<slug>.md`。
3. 优先复用已有服务、官方组件与标准库，不为几行代码引入依赖或框架。
4. 保留用户明确决定：四环境隔离、只读引用与导入分离、导入确认、真实界面验收。改变这些决定需要用户明确指示。

## 修改与回归

- Bug 先复现报告人的输入和界面，再检查共享实现的同类调用方，不只修截图中一个来源。
- 新增非平凡分支、循环或解析器有小而有意义的回归测试；文档和简单格式调整无需形式化测试。
- Bug 回归测试应在旧实现上因目标行为失败（red），修复后通过（green）。用隔离副本/临时 worktree 验证旧实现，不回滚用户工作目录。编译失败、缺依赖和跳过不是有效 red。
- 解析、安全、数据写入或去重的关键断言，再做定向 break check：在隔离副本中故意破坏目标条件，测试必须抓到；简单改动可说明 N/A。
- 使用真实服务验收受影响集成；样例用于隔离数据，演示替身不证明真实接口可用。
- 代码搬移保留错误处理、校验与取消逻辑；失败不能被吞掉后显示成功。日志不泄露凭据或会话正文。
- README 中英文同步，保留开头展示区。UI 使用现有 DSH 组件和 `design.md`。

## 完成条件

- 相关测试与类型检查通过；代码交付执行 `npm run agent:verify`（完整 check + 双环境刷新），不能忽略失败。
- 在 `agent-browser-test` 完成受影响浏览器验收，Desktop 确认实际窗口，两者分别记录。
- 审查最终 diff，检查越界改动、泄密、接口/旧数据兼容性，并列明没跑的测试。
- 验证结果绑定实际候选内容，后续变更使旧结果失效；不能凭旧 SHA 或日志放行。
- 有 PR/CI 时，只接受当前 HEAD 已完成且成功的必要检查；queued、running、cancelled、旧 SHA 均不是通过。授权合并时使用平台支持的 HEAD 匹配保护。
- 发布遵守专门清单。命令退出码、手工证据和产品结论分别记录，不因检查困难降低验收标准。
